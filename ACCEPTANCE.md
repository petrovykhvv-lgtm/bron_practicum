# Чек-лист локальной приёмки

Как пользоваться: разверните проект по [README.md](README.md) (разделы 1–5), затем пройдите пункты сверху вниз и отметьте `[x]`. Логины и пароли — в рамке «Демо-доступ» на главной и на `/login` (и в `.env`). Результаты прогона разработчика и найденные ошибки — в [CHECKS.md](CHECKS.md), этап 9. Автоматически почти всё из блоков B–F проверяется командой `npm run smoke`. Время в базе хранится как `timestamptz`, приложение работает в UTC; если время броней в интерфейсе сдвинуто, см. раздел «Частые проблемы» README.

## A. Развёртывание

- [ ] `.env` создан из `.env.example`; в репозитории `.env` нет (`git ls-files | grep env` показывает только `.env.example`).
- [ ] `npm install` проходит без ошибок на чистой копии (предупреждения `install-scripts` допустимы).
- [ ] `npm run db:migrate` применяет 4 миграции (`init`, `booking_constraints`, `timestamptz`, `table_change_enums`); повторный запуск пишет «No pending migrations».
- [ ] `npm run db:seed` создаёт 4 пользователей, 8 столов, 6 броней; повторный запуск не создаёт дублей («бронирования уже есть»).
- [ ] `npm run dev` или `npm run build && npm start` открывает http://localhost:3000.
- [ ] На главной и на `/login` в правом верхнем углу есть рамка «Демо-доступ».

## B. Регистрация, вход, роли

- [ ] `/register`: новый пользователь создаётся и сразу входит; роль в кабинете «Гость».
- [ ] Неверный пароль на `/login` даёт сообщение «Неверный email или пароль» (то же для несуществующего email).
- [ ] Вход под `admin`, `super_admin`, `guest1`: в шапке и кабинете роль соответствует.
- [ ] Пять неверных паролей подряд для одного email: шестая попытка отвечает «Слишком много неудачных попыток» (429); другие пользователи входят свободно.
- [ ] «Выйти» закрывает сессию: `/account` и `/admin` перенаправляют на `/login`.
- [ ] Гость открывает `/admin`, `/admin/bookings`, `/admin/users`: попадает на `/account` с сообщением о недостатке прав.

## C. Бронирование гостя

- [ ] `/book`: число гостей 1–8; даты только вторник–воскресенье, не дальше 14 дней, прошедшего времени нет.
- [ ] Время: сетка 12:00, 13:30, 15:00, 16:30, 18:00, 19:30, 21:00; занятых окон нет.
- [ ] Для 8 гостей окно исчезает, когда занят единственный стол на 8 (проверка: гость 1 бронирует 8 гостей на время T, гость 2 уже не видит T).
- [ ] Созданная бронь в статусе «Ожидает», в «Мои брони» указан назначенный стол и срок отмены.
- [ ] Вторая бронь того же гостя на то же время невозможна (окно скрыто; через API `409 user_conflict`).
- [ ] Уведомление «Заявка принята» появляется в «Уведомлениях», счётчик в шапке растёт; «Отметить всё прочитанным» его обнуляет.
- [ ] Отмена до дедлайна работает: статус «Отменена», окно снова свободно, уведомление «Бронь отменена».
- [ ] За 3 часа и меньше до начала кнопки «Отменить» нет, сообщение «Срок самостоятельной отмены прошёл».

## D. Администратор (`admin`)

- [ ] `/admin`: показатели, очередь заявок, таблица «Что доступно ролям».
- [ ] `/admin/bookings`: у каждой брони видны гость, назначенный стол, статус (в том числе «Не пришёл» у seed-брони); список постраничный (по 50), ссылки «Назад/Вперёд» сохраняют фильтры.
- [ ] Фильтры: по статусу, по датам «с/по», быстрые («Ожидают решения», «Сегодня», «Ближайшие 7 дней», «Не пришли»), «Сбросить».
- [ ] Подтвердить `pending`: статус «Подтверждена», гость получает уведомление.
- [ ] У `confirmed` до начала брони доступна только «Отменить» (подсказка: завершить и «Не пришёл» можно после начала); после начала появляются «Завершить» и «Не пришёл». У конечных статусов кнопок нет («Статус конечный»).
- [ ] «Отменить» и «Не пришёл» красные и требуют подтверждения в диалоге (Escape и «Назад» отменяют действие).
- [ ] Пересадка: у активной брони в списке есть «Пересадить за…» со столами, которые подходят по вместимости и свободны; после пересадки в «Столе» новое значение, гость получил уведомление «Стол изменён», в истории брони запись «Изменён стол брони».
- [ ] `/admin/floor`: план зала на день (столы × время), гость, число гостей и статус в ячейках, закрытые окна, переключение дней, понедельник — «Выходной».
- [ ] Из `cancelled`, `completed`, `no_show` вернуть бронь в активный статус невозможно ни кнопкой, ни через API (`409`).
- [ ] `/admin/slots`: закрыть окно с причиной, оно исчезает у гостей; открыть обратно, оно возвращается. При закрытии окна с бронями показывается предупреждение и ссылка на брони дня.
- [ ] `/admin/users`: список без паролей, кнопок смены роли нет; сообщение, что роли меняет только суперадминистратор.
- [ ] `/admin/history`: видны брони и окна; смены ролей и регистраций нет.

## E. Суперадминистратор (`super_admin`) и история

- [ ] `/admin/users`: у пользователей и администраторов есть кнопки «Сделать администратором» / «Сделать гостем»; у `super_admin` кнопки нет.
- [ ] Повышение гостя до `admin`: его новая роль действует сразу (без повторного входа открывается `/admin`); понижение закрывает доступ.
- [ ] `/admin/history` (под `super_admin`): записи о регистрации и смене роли с автором и временем.
- [ ] История каждой брони («История» в списке) показывает: кто и когда создал, подтвердил, отменил (рестораном или гостем), завершил, отметил «не пришёл».

## F. Безопасность

- [ ] Пароли хранятся хешами: `psql -d verde_marea -c 'select email, left("passwordHash",7) from "User"'` показывает `$2b$12$` у всех.
- [ ] В ответах API нет `passwordHash` (`/api/auth/me`, `/api/admin/users`, `/api/admin/audit`).
- [ ] Админский API без прав: гость получает `403`, аноним `401` (`curl -i http://localhost:3000/api/admin/bookings`).
- [ ] `admin` не может менять роли (`403`); роль `super_admin` не меняется никем (`403`).
- [ ] Две вкладки: параллельные попытки занять один стол не создают двух броней (проверено автотестами на гонки).

## G. Дизайн

- [ ] Все экраны в одной системе: стеклянные карточки, зелёные капсульные кнопки, засечные заголовки с курсивным акцентом, золотые акценты.
- [ ] Гостевые экраны и админка выглядят частями одного продукта (одинаковые шапка, бейджи статусов, чипы, пустые состояния); админские таблицы на более плотных поверхностях.
- [ ] Выбор даты и времени на `/book` управляется с клавиатуры: Tab заходит в группу один раз, стрелки меняют выбор, Home/End прыгают к краям.
- [ ] Мобильное меню закрывается после перехода на другую страницу.
- [ ] Главная: арка «Режим работы», три шага, при наличии файлов в `public/photos` — фото и галерея.
- [ ] На узком экране (375 px) нет горизонтального скролла, шапка сворачивается в «Меню», строки админской таблицы становятся карточками.
- [ ] Видимый focus при навигации с клавиатуры (Tab).
