# Plan.md — план реализации Verde Marea

Принцип: сначала данные и правила, потом API, потом интерфейс. Каждый этап заканчивается проверкой и записью в журнал проверок.

## Этап 1. Рамки и план (выполнен)
- Готово: `SPEC.md`, `Plan.md`, `AGENTS.md`, `design.md`, `CLAUDE.md`.
- Выход: допущения из `SPEC.md` утверждены.

## Этап 2. Каркас и окружение (выполнен)
- Next.js + TypeScript + Tailwind, npm-скрипты.
- `.env.example`, подключение к локальному PostgreSQL, Prisma.
- Токены `design.md` в конфиге Tailwind.
- Проверка: проект стартует, подключение к БД работает.

## Этап 3. Модель данных, права, контрольные данные (выполнен)
- Схема Prisma: `User`, `Table`, `Slot`/правила окон, `Booking`, `Notification`, `AuditLog`.
- Ограничения БД на пересечения (стол, пользователь) там, где это возможно.
- Миграции, `seed` (столы, тестовые пользователи всех ролей), `reset`.
- Проверка: `reset` + `seed` проходят с нуля, повторно запускаются без ошибок.

## Этап 4. Бэкенд: доступ (выполнен)
- Регистрация, вход (`bcryptjs`, 12 раундов), сессия.
- Серверная проверка ролей; матрица прав из `SPEC.md`.
- Ответы API никогда не содержат `passwordHash`.
- Zod-схемы на всех входах.

## Этап 5. Бэкенд: бронирование (выполнен вместе с гостевым интерфейсом)
- Расчёт доступных окон по правилам.
- Подбор стола, создание брони в транзакции.
- Машина состояний, дедлайн отмены (3 часа), инварианты.
- Уведомления и `AuditLog` при каждом значимом действии.

## Этап 6. Бэкенд: администрирование (выполнен)
- Список броней с фильтрами (статус, дата).
- Смена статусов, управление окнами записи.
- Управление ролями (`super_admin`), защита роли `super_admin`.

## Этап 7. Фронтенд: гость и единый интерфейс (выполнен)
- Регистрация/вход, выбор даты-времени-гостей, создание брони.
- «Мои брони», отмена, уведомления.
- Компоненты по `design.md`.

## Этап 8. Фронтенд: админ-контур (выполнен в этапе 6)
- Таблица броней, фильтры, смена статусов, отображение стола.
- Управление окнами, ролями, просмотр истории.

## Этап 9. Проверки и приёмка (выполнен)
- Сквозной сценарий на чистой копии: запуск → миграции → seed → регистрация → вход → бронирование → уведомления → статус администратором → смена роли → история.
- `README.md` как runbook: окружение, база, миграции, seed, роли, базовая проверка, безопасное обновление, частые проблемы.
- [ACCEPTANCE.md](ACCEPTANCE.md) — чек-лист приёмки; `npm run smoke` — автоматическая сквозная проверка (48 проверок).
- [CHECKS.md](CHECKS.md) — журнал проверок и найденных ошибок (4 исправлены, связанные функции перепроверены).

## Этап 10. Доработки после самооценки (выполнен)
- Архитектура: `timestamptz` и UTC-соединение, защита тестовой базы, ограничение попыток входа, постраничные списки, правило «завершить после начала».
- Продукт: пересадка гостей, план зала. Дизайн: плотные админские поверхности, диалоги подтверждения, доступный выбор окон, главная с аркой и галереей фото.
- Журнал и найденные ошибки: [CHECKS.md](CHECKS.md), этап 10.
