# Verde Marea — бронирование столов

Локальная система бронирования столов ресторана Verde Marea: гость выбирает дату, время и число гостей, видит только доступные окна и создаёт бронь; администратор ведёт поток броней, окна записи и историю; суперадминистратор управляет ролями. Next.js, React, TypeScript, Tailwind CSS, Zod, PostgreSQL, Prisma, npm.

Документы: [SPEC.md](SPEC.md) (спецификация, роли, правила, API) · [Plan.md](Plan.md) (этапы) · [design.md](design.md) (визуальная система) · [AGENTS.md](AGENTS.md) (контекст и правила работы с ИИ) · [ACCEPTANCE.md](ACCEPTANCE.md) (чек-лист приёмки) · [CHECKS.md](CHECKS.md) (журнал проверок и исправлений).

## Быстрый старт

Если Node.js и PostgreSQL уже установлены и PostgreSQL запущен:

```bash
git clone https://github.com/petrovykhvv-lgtm/bron_practicum.git
cd bron_practicum
cp .env.example .env          # затем замените USER в адресах БД на своего пользователя PostgreSQL
createdb verde_marea
createdb verde_marea_test     # нужна только для тестов
npm install
npm run db:setup              # миграции + клиент Prisma + seed
npm run dev                   # http://localhost:3000
```

Откройте http://localhost:3000: на главной и на `/login` в правом верхнем углу показана рамка «Демо-доступ» с логинами и паролями. Проверить работу одной командой: `npm run smoke` (в другом терминале, пока сервер запущен).

Ниже те же шаги подробно.

## 1. Подготовка окружения

| Что | Версия | Как проверить |
|---|---|---|
| Node.js | 20 и новее (проверено на 26) | `node -v` |
| npm | 10 и новее (в комплекте с Node.js) | `npm -v` |
| PostgreSQL | 14 и новее (проверено на 16) | `psql --version` |

Установка, если чего-то нет:

```bash
# macOS (Homebrew)
brew install node postgresql@16

# Debian/Ubuntu
sudo apt install nodejs npm postgresql
```

## 2. Запуск базы данных

```bash
# macOS (Homebrew)
brew services start postgresql@16

# Linux
sudo systemctl start postgresql
```

Проверьте, что сервер принимает подключения:

```bash
pg_isready                    # ожидается: accepting connections / принимает подключения
```

Создайте базы (имена можно менять, тогда поправьте адреса в `.env`):

```bash
createdb verde_marea          # рабочая база приложения
createdb verde_marea_test     # отдельная база для автотестов
```

Если `createdb` отвечает, что роли не существует или нужен пароль: на macOS с Homebrew подходит ваш системный пользователь без пароля; на Linux создайте роль командой `sudo -u postgres createuser -s "$USER"` либо укажите в `.env` пользователя и пароль: `postgresql://пользователь:пароль@localhost:5432/verde_marea`.

## 3. Настройка `.env`

```bash
cp .env.example .env
```

Откройте `.env` и замените `USER` в `DATABASE_URL` и `TEST_DATABASE_URL` на имя пользователя PostgreSQL (на macOS это `whoami`). Файл `.env` содержит локальные значения и никогда не попадает в git (в репозитории только `.env.example`).

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | рабочая база приложения |
| `TEST_DATABASE_URL` | база для интеграционных тестов (тесты сами применяют миграции и очищают её; не указывайте рабочую базу) |
| `RESTAURANT_TZ` | часовой пояс ресторана: по нему считаются дни недели и время окон (по умолчанию `Europe/Moscow`) |
| `SEED_SUPER_ADMIN_EMAIL`, `SEED_SUPER_ADMIN_PASSWORD` | вход суперадминистратора, создаваемого seed |
| `SEED_DEMO_PASSWORD` | пароль администратора и двух гостей из seed |
| `SHOW_DEMO_ACCOUNTS` | рамка с демо-доступом на главной и `/login` показывается **только при `"true"`** (в `.env.example` включено); без переменной пароли на страницах не появляются |
| `SESSION_COOKIE_SECURE` | `false` по умолчанию (запуск по `http://localhost`); `true` только если приложение открывается по HTTPS |

## 4. Установка зависимостей, миграции, seed

```bash
npm install                   # зависимости; клиент Prisma генерируется автоматически
npm run db:migrate            # применить миграции (prisma migrate deploy)
npm run db:seed               # контрольные данные
```

Все три шага разом (миграции, клиент, seed): `npm run db:setup`.

- Миграции лежат в `prisma/migrations/`: `init` (таблицы), `booking_constraints` (защита от дублей на уровне БД: пересечения по столу и по пользователю, вместимость, границы значений), `timestamptz` (моменты времени с часовым поясом, ограничения на `tstzrange`), `table_change_enums` (смена стола в истории). Команда применяет только ещё не применённые миграции и ничего не удаляет; при переходе с `timestamp` на `timestamptz` существующие данные сохраняются (значения считались UTC и преобразуются явно).
- `npm run db:seed` безопасен при повторном запуске: существующих пользователей, столы и брони не трогает, демо-брони создаёт только в пустой таблице бронирований.
- `npm run db:reset` **удаляет все данные**, применяет миграции с нуля и запускает seed. Только для локальной разработки.

Предупреждения `npm warn install-scripts` при установке безопасны: они касаются необязательных скриптов зависимостей.

## 6. Входы по ролям

Seed создаёт четыре учётные записи (значения паролей — в вашем `.env`; они же показаны в рамке «Демо-доступ» на главной и на `/login`):

| Роль | Email | Пароль |
|---|---|---|
| `super_admin` | значение `SEED_SUPER_ADMIN_EMAIL` (по умолчанию `superadmin@verdemarea.local`) | `SEED_SUPER_ADMIN_PASSWORD` |
| `admin` | `admin@verdemarea.local` | `SEED_DEMO_PASSWORD` |
| `user` | `guest1@verdemarea.local`, `guest2@verdemarea.local` | `SEED_DEMO_PASSWORD` |

Также seed создаёт 8 столов (3 на 2 места, 3 на 4, 1 на 6, 1 на 8) и 6 демо-броней во всех статусах.

### Как создать пользователя каждой роли

- **`user`**: страница `/register` (роль гостя назначается всегда, выбрать другую при регистрации нельзя).
- **`admin`**: зарегистрировать пользователя, затем войти под `super_admin`, открыть «Администрирование → Пользователи» и нажать «Сделать администратором». Понизить обратно можно там же. Только `super_admin` меняет роли.
- **`super_admin`**: только через seed (из приложения эту роль назначить нельзя). Укажите в `.env` новые `SEED_SUPER_ADMIN_EMAIL` и `SEED_SUPER_ADMIN_PASSWORD` и выполните `npm run db:seed`: будет создан ещё один суперадминистратор, существующие аккаунты не изменятся.

## 7. Базовая локальная проверка

**Автоматически.** При запущенном сервере (`npm run dev` или `npm start`) в другом терминале:

```bash
npm run smoke
```

Скрипт [scripts/smoke.ts](scripts/smoke.ts) проходит весь сценарий (61 проверка) и завершается кодом 0 при успехе: анонимный доступ и настоящие 307-редиректы защищённых страниц → регистрация → вход и выход → защита от подбора пароля (429) и CSRF → бронирование (в том числе отказы: прошлое время, дубль, 9 гостей) → «Мои брони» и уведомления → вход `admin`, фильтры, постраничный список, подтверждение, запрет завершения до начала, пересадка гостей, план зала → отмена гостем → закрытие и открытие окна → отказы по ролям → вход `super_admin`, смена роли и возврат → история изменений (постранично) для `super_admin` и `admin`. Другой адрес сервера: `SMOKE_BASE_URL=http://localhost:3100 npm run smoke`. Скрипт оставляет в базе пользователя `smoke.<время>@verdemarea.local` (бронь отменена, окно открыто, роль возвращена); `npm run db:reset` очищает всё.

**Вручную** (то же глазами, около 10 минут), подробности и галочки — в [ACCEPTANCE.md](ACCEPTANCE.md):

1. `/register`: создайте гостя, после регистрации вы вошли.
2. `/book`: 2 гостя → дата → время → «Забронировать». Окна вторника–воскресенья, прошлого времени нет.
3. «Мои брони»: бронь в статусе «Ожидает», назначен стол, указан срок отмены. «Уведомления»: «Заявка принята».
4. Выйдите, войдите как `admin`: «Администрирование → Брони»: найдите бронь, нажмите «Подтвердить». История брони показывает, кто и когда.
5. Снова как гость: уведомление «Бронь подтверждена». Отмените бронь.
6. Как `admin` откройте «Окна записи», закройте окно: оно пропало из `/book`. Откройте обратно.
7. Как `super_admin`: «Пользователи» → повысьте гостя до администратора, затем понизьте. «История»: смена ролей с автором.

## 9. Безопасное обновление после изменений схемы или серверной логики

Порядок для базы с данными, которые жалко потерять:

1. **Резервная копия** (хранить вне репозитория):
   ```bash
   mkdir -p ~/verde_marea-backups
   pg_dump verde_marea > ~/verde_marea-backups/verde_marea-$(date +%F).sql
   ```
2. **Получить изменения и зависимости**: `git pull`, затем `npm install`.
3. **Применить новые миграции**: `npm run db:migrate`. Команда применяет только новые миграции, ничего не пересоздаёт; если новых нет, сообщит «No pending migrations».
4. **Обновить клиент Prisma**: `npm run db:generate` (выполняется и при `npm install`).
5. **Проверить**: `npm run typecheck && npm test`, перезапустить сервер и выполнить `npm run smoke`.
6. **Откат при проблеме**: остановить сервер, пересоздать базу из копии:
   ```bash
   dropdb verde_marea && createdb verde_marea
   psql verde_marea < ~/verde_marea-backups/verde_marea-ГГГГ-ММ-ДД.sql
   ```

Если меняете схему сами: правьте `prisma/schema.prisma`, затем `npx prisma migrate dev --name краткое_описание` (на локальной базе) и коммитьте созданную миграцию. Правила, которых Prisma не выражает (исключающие ограничения, триггеры), добавляйте в SQL-миграцию: `npx prisma migrate dev --create-only --name ...`, правка файла, применение, как сделано в `booking_constraints`. Уже применённые миграции не редактируйте. После изменений схемы обязательно прогоните `npm test` (там проверяются ограничения БД) и `npm run smoke`. Изменения серверной логики не требуют миграций: тесты, перезапуск сервера, `npm run smoke`. Сессии хранятся в базе и переживают перезапуск.

## 10. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Cannot resolve environment variable: DATABASE_URL` | нет `.env`: `cp .env.example .env` и поправьте `USER` |
| `Can't reach database server` / `ECONNREFUSED` | PostgreSQL не запущен: раздел 2, `pg_isready` |
| `database "verde_marea" does not exist` | `createdb verde_marea` |
| `role "USER" does not exist` | в `.env` не заменён `USER` на реального пользователя PostgreSQL |
| `EADDRINUSE: address already in use :::3000` | порт занят другим приложением: `npm run dev -- -p 3100` |
| тесты пропущены или падают на подключении | не создана `verde_marea_test` или неверный `TEST_DATABASE_URL` |
| тесты останавливаются с сообщением «…не содержит «test»» или «совпадает с DATABASE_URL» | сработала защита рабочей базы: тесты очищают таблицы, поэтому `TEST_DATABASE_URL` должен быть локальной базой с «test» в имени (`createdb verde_marea_test`) |
| вход отвечает «Слишком много неудачных попыток» (429) | пять неверных паролей подряд для этого email: подождите 15 минут или перезапустите сервер (счётчики в памяти процесса) |
| время броней сдвинуто на несколько часов | клиент Prisma создан не через `createPrismaClient` (он закрепляет сессию в UTC); см. `tests/timezone.test.ts` |
| на `/login` нет рамки с демо-доступом | `SHOW_DEMO_ACCOUNTS="false"` в `.env` или нет `SEED_*` переменных |
| после входа сразу выкидывает на `/login` | включён `SESSION_COOKIE_SECURE="true"`, а приложение открыто по `http://`: поставьте `false` |
| шрифты не загрузились при сборке | `next/font` скачивает Cormorant Garamond и Manrope при сборке и первом запуске: нужен интернет; без него применяются запасные шрифты (Georgia, системный) |
