# Verde Marea — система бронирования столов

Репозиторий: https://github.com/petrovykhvv-lgtm/bron_practicum.git (ветка `main`)

Правила работы с ИИ — в [AGENTS.md](AGENTS.md). Спецификация — [SPEC.md](SPEC.md), план — [Plan.md](Plan.md), визуальная система — [design.md](design.md).

## Цель проекта

Собрать систему бронирования столов в ресторане Verde Marea с **локальным запуском**: интерфейс, серверная логика, база данных, упрощённая авторизация, роли, правила бронирования, административный контур, история изменений, визуальная система Verde Marea, `README.md`/runbook, проверки.

## Пользователи и роли

| Роль | Что важно |
|---|---|
| Гость (`user`) | Быстро выбрать дату, время и число гостей; видеть только доступные варианты; создать бронирование; найти его в личном кабинете. |
| `admin` | Видеть поток бронирований; подтверждать и отменять заявки; управлять окнами записи; видеть назначенный стол; не терять историю действий. |
| `super_admin` | Всё, что у `admin`, плюс управление ролями пользователей и другие служебные действия. |

## Ключевые требования

- У гостей нет доступа к административной части.
- Все критические ограничения (роли, доступ, правила бронирования, доступность столов) проверяются **на сервере**; клиентские проверки только для удобства.
- Гость видит только доступные варианты.
- Каждое действие админов и изменение бронирований пишется в историю изменений.
- Назначенный стол виден в бронировании.
- Только `super_admin` меняет роли пользователей; `admin` не управляет ролью `super_admin`.

## Пользовательский сценарий

1. Запуск локально. 2. Миграции и `seed`. 3. Регистрация и вход. 4. Сессия. 5. Выбор даты, времени, числа гостей (только допустимые окна). 6. Бронь в `pending`, стол назначается автоматически. 7. «Мои брони» и внутренние уведомления. 8. Отмена до дедлайна. 9. `admin` фильтрует брони и меняет статусы. 10. `super_admin` меняет роль; история фиксирует ключевые действия.

## Стек и требования к реализации

- Next.js, React, TypeScript, Tailwind CSS, Zod, PostgreSQL, Prisma, npm. Локальный запуск.
- Пароли: хранится только `passwordHash` от `bcryptjs` с 12 раундами соли.
  - Регистрация: `bcryptjs.hash(password, 12)`; вход: `bcryptjs.compare(inputPassword, user.passwordHash)`.
  - Запрещено: открытый пароль, MD5/SHA-хеши, собственные схемы соли.
- Валидация входных данных на сервере через Zod.
- Визуальная система Verde Marea по [design.md](design.md): цвета `#1F4D3A`, `#C7A76C`, `#F5F1E8`, `#1B1B1B`; шрифты Cormorant Garamond и Manrope; единые токены.

## Ограничения проекта

**Рамки:** самостоятельный продукт Verde Marea, не переделанная референс-сборка; без внешних интеграций, публичного деплоя и лишнего продакшен-контура.

**Артефакты:** локальный PostgreSQL, `.env.example`, схема Prisma, миграции, команды `seed` и `reset`, `README.md`/runbook, спецификация, `Plan.md`, `AGENTS.md`, `design.md`, чек-лист локальной приёмки, журнал проверок.

**Сущности:** `User`, `Table`, `Slot` (или эквивалентный механизм окон), `Booking`, `Notification`, `AuditLog`. **Роли:** `user`, `admin`, `super_admin`; нужна матрица ролей.

**Безопасность:** регистрация, вход, сессия, проверка ролей на сервере; `passwordHash` (bcryptjs, 12) никогда не попадает в UI и API-ответы; `admin` не управляет `super_admin`; `super_admin` повышает пользователя до `admin` и понижает обратно.

**Окна считаются по правилам:** 14 дней вперёд; вторник–воскресенье; шаг 90 минут, 12:00–21:00; без прошедшего времени; без занятых окон; только при наличии подходящего стола.

**Столы и брони:** стол подбирается по вместимости и сохраняется в брони; стол нельзя назначить двум броням на пересекающееся окно; у пользователя не может быть двух активных броней на одно время; статусы `pending`, `confirmed`, `cancelled`, `completed`, `no_show`, переходы ограничены ролями и дедлайном; самостоятельная отмена не позднее чем за 3 часа до начала; `admin` и `super_admin` подтверждают, отменяют, завершают и отмечают `no_show`; список броней фильтруется по статусу и дате; `AuditLog` фиксирует действия по броням и смену ролей.

## Статус

- Этап 1 (рамки, SPEC, Plan, AGENTS, design) выполнен, допущения утверждены.
- Этап 2 (каркас): Next.js, Prisma 7 + PostgreSQL (`verde_marea`, `verde_marea_test`), Zod, bcryptjs, vitest.
- Этап 3 (модель данных, права, seed): схема, две миграции, seed, правила, матрица ролей и тесты готовы (журнал — [CHECKS.md](CHECKS.md)). `db:reset` проверен.
- Этап 4 (auth-lite, роли): регистрация, вход, выход, сессии в БД (cookie `vm_session`, хранится хеш токена), серверная проверка прав, смена ролей, страницы `/login`, `/register`, `/account`, `/admin/users`. 54 теста.
- Этап 5 (сценарий бронирования): доступные окна, подбор стола, создание `pending`, «Мои брони», отмена до дедлайна, уведомления, страницы `/book`, `/bookings`, `/notifications`. 75 тестов. Подробности — SPEC.md, раздел 7b.
- Этап 6 (админ-контур и история): `/admin` (обзор), `/admin/bookings`, `/admin/slots`, `/admin/history`, `/admin/users`; смена статусов по машине состояний, закрытие окон, история с автором и временем. 107 тестов. Подробности — SPEC.md, раздел 7c.
- Дальше — этап 9 (проверки и приёмка: чек-лист локальной приёмки, финальный README/runbook, сквозной прогон с нуля).

## Команды

`npm run db:setup` (миграции + клиент + seed), `npm run db:seed`, `npm run db:reset` (сброс БД, требует согласия пользователя в агентной сессии), `npm test`, `npm run typecheck`.
